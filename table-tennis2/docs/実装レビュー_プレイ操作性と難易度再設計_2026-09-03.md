## 2. 指摘事項

### IR-01 [P2] 縦到達性テストが新しいAI球速・精度を適用していない

- 根拠: [reachable-contact.test.ts](../tests/reachable-contact.test.ts) L88–98の`solveShot()`呼び出しは`pace` / `precision`を省略する。難易度差を適用するのはL143以降の補助倍率だけである。[game.ts](../src/game.ts) L913–926の製品経路ではAIに`LEVEL_PLAY[level].aiPace` / `aiPrecision`を渡す。
- 要求: 正本§4.3・§9.1・G1は、新プロファイルによる弾道の変化を含めて3難易度の到達不能0件・最小margin > 0を検査する。
- 確認: 現行テストの採用数は**30,329件**。同じ生成器へ製品と同じ2引数だけをメモリ内で追加すると**30,854件**となり、最小marginも下表のように変わった。どちらも現時点では合格するが、現在の回帰テストが別の球を検査していることは明確である。

| 難易度 | 現行テスト fine / touch | 新AI引数を適用した fine / touch |
|---|---|---|
| 初級 | 8.074 / 12.568px | 19.570 / 24.064px |
| 中級 | 3.461 / 7.416px | 3.500 / 7.455px |
| 上級 | 3.356 / 6.951px | 2.659 / 6.254px |

- 影響: AIの難易度調整で打点が移動して到達不能が発生しても、旧引数のテストは成功し得る。実装ログの「新母集団で検証済み」を継続的に保証できない。
- 修正方針: AI返球へ製品と同じpace / precisionを注入し、採用母集団とmarginを記録する。旧Y min 0.45の負の対照は維持する。今回の追加引数では旧対照のfine 6件 / touch 3件も維持された。
- 再確認条件: 3難易度・5 viewport・両pointerの新母集団で到達不能0件かつ最小margin > 0。件数そのものを新しい合格条件にはしない。

### IR-02 [P2] フロア・旧互換・飽和の負の対照が要求する性質を検査していない

根拠は[新規単体テスト](../tests/level-play.test.ts)と正本§9.2、G1。以下を同じ「負の対照完了」として扱っている。

| U-B1、L326–376 | **同じ新solver**の引数省略と明示的な`1 / 1`を比較する | 旧solverとの比較もdirect側の検査もない。新solverの出力速度を常に半分にした差し替えでもこのケースは成功した |
| U-A4、L225–238 | 有限・正・`need <= 1300 × margin` | 使用打点の実測値は**940.333496**で、飽和値**1508**へ達していない。探索上限へ到達する境界を通していない |
| U-A6、L285–324 | 定数1.16と、独自PUSH計算の`gapFor(1.03) < 0.1` | 既存校正のLCG・3打点ではなくmulberry32・中央1打点を使い、solver処理を複製している。1.16で4技の§6.3値が一致する検査はない |

- 影響: G1に明示されたU-A3 / U-B1等の完了根拠にならない。テスト名と成功表示から、実際には行っていない互換性・境界検証を完了と読み取れてしまう。
- 補足: 速度半減の差し替えはU-B1単体の検出能力を確認したもの。既存`game-core.test.ts`のU33は5技の固定出力を別途検査しており、全suiteが速度半減を見逃すという意味ではない。
- 修正方針: 旧版fixtureまたは変更前コードを比較対象にし、同じ入力と乱数列で全出力を比較する。U-A3は**solverへ渡したintentのpower・技種・spinから**区画分けする。U-A6は既存`direct-calibration`の生成条件を共有し、物理処理のコピーを避ける。U-A4は実際に上限へ達する入力と境界前の入力を用意する。

- 再確認条件: 対象比較が正常実装で成功し、フロアの削除・不要な速度変更・飽和上限の変更をそれぞれ検出する。G1記録に対応するケースと比較元を記載する。

### IR-03 [P2] 難易度別接触の結合検証と返球猶予の回帰ゲートが不足している

- 根拠: [level-play.test.ts](../tests/level-play.test.ts) L122–148のU-A1は`ContactEvent`へ品質下限を直接セットする。L486–503のU-C2は定数の大小比較だけで、30組の投影楕円を検査しない。L505–600のU-C5はcontrollerのgetter / debugを確認するが、描画・接触関数との結合、resetを挟まないpointer切替、猶予失効、penを通していない。
- [paddle-contact.test.ts](../tests/paddle-contact.test.ts)の全呼び出しは品質下限0.4を使用する。既存[direct-calibration.test.ts](../tests/direct-calibration.test.ts) L146–220の結合ケースも`z=-100`・touchのみで、終端の確認は有限値までである。U-D1が要求する`z=-178`、touch初級 / fine上級、非ゼロincoming spinから**相手コート着地まで**の検査を代替できない。
- 確認: 製品の`contact.ts` L128–130をメモリ内で「注入された下限を無視し、常に0.4を使う」に差し替えても、`level-play` / `paddle-contact` / `direct-calibration`の**22/22が成功**した。初級0.55・中級0.47が失われる回帰を、この試験群は検出できない。
- 返球猶予: 正本U-C1の「初級p50 ≥ 0.45s、中級 ≥ 0.40s、上級0.27–0.30sと単調性」をassertするテストがない。[measure-play-balance.mjs](../scripts/measure-play-balance.mjs) L267–301は表示のみで、[package.json](../package.json)の`check`にも含まれない。今回の値は合格するが、自動ゲートには固定されていない。
- 影響: 数値表・単体119件の成功は、実接触へ難易度設定が適用され続けることや返球猶予を保証しない。前回R-02の原因に対する実装方針は正しいものの、再発防止の結合条件が未完である。
- 修正方針: U-C3 / U-C5 / U-D1を製品の接触→intent→solver経路で実行し、各難易度の品質下限・補助輪郭・着地点を検査する。U-C1は生成器Aを再利用した決定論的assertとしてunitまたは`check`へ接続する。U-C4も既存の乱数試験でカバーする範囲と新パラメータ経路の追加分を明示する。
- 再確認条件: 上記の品質下限0.4固定への差し替えで必ず失敗し、正常時は3難易度のライフサイクル結合・遠距離返球・返球猶予の条件を満たす。
