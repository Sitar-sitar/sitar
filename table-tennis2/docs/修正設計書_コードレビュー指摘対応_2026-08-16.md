## 3. 現状・原因・制約

### 3.1 CR-P1：右レールの縦方向余白

- `src/styles.css` の `.app-rail--right` は `display: flex; flex-direction: column; overflow: hidden` である。
- `.app-rail--right .serve-controls` は汎用fixedパネルを `position: static` に上書きし、通常のflex子要素として配置する。
- プレイヤーサーブ時は設定ボタン、`play-status`、サーブラベル、9個の球種ボタン、3個の長さボタン、各gap/padding/borderが同じ縦領域を使用する。
- 既存の低高さmedia queryはパネルpaddingとラベル余白だけを縮める。レビュー環境と現在のローカル再実行で結果が異なるため、`bottom <= 320`だけでは描画差への余裕がない。
- 既存E2Eは設定ボタンと12個のサーブボタンについて44×44px以上を要求する。このアクセシビリティ契約は圧縮対象にしない。

### 3.2 CR-P2：開発依存の解決

前提lockfileの依存経路は次のとおりで、いずれも `dev: true` である。

```text
eslint@10.8.0
└─ minimatch@10.2.5
   └─ brace-expansion@5.0.8

vite@8.1.5
└─ postcss@8.5.23
   └─ nanoid@3.3.16
```

- `brace-expansion` の対象アドバイザリは [GHSA-rgw5-rvv9-x895](https://github.com/advisories/GHSA-rgw5-rvv9-x895) であり、5系の修正版下限は `5.0.9` である。
- `nanoid` の対象アドバイザリは [GHSA-2v37-7h3g-55p8](https://github.com/advisories/GHSA-2v37-7h3g-55p8) であり、3系の修正版下限は `3.3.18` である。
- 2026-08-16時点のnpm audit結果は0件だが、lockfileの実バージョンは修正版下限未満である。外部監査データの反映時差や判定差を考慮し、両方の証拠を別々に検査する。
- 親依存の宣言範囲は同じmajor内の修正版を許容している。第一選択はlockfile内の間接依存だけを互換版へ更新することである。

### 3.3 CR-P3：Service Worker登録失敗

- `src/main.ts` はService Worker API非対応時には何もしない。
- `data-service-worker` が未定義の場合は構成不備として同期的に例外を投げる。このfail-fast契約は維持する。
- 登録Promiseのrejectだけが黙殺されている。登録失敗はオフライン/PWA機能の縮退であり、CanvasゲームやIndexedDB戦績まで停止する理由にはしない。
- 警告へ渡すのは固定メッセージと受け取ったエラーだけとし、入力軌跡、プレイヤー名、保存値を追加で記録しない。

## 4. 設計方針

### 4.1 採用方針

| 対象 | 採用方針 | 理由 |
|---|---|---|
| CR-P1 | compactかつ低高さの時だけspacingを縮め、44px操作領域を維持 | 製品要件を変えず、影響を右レールのプレイヤーサーブ時へ限定できる |
| CR-P2 | 間接依存を同一majorの修正版へlockし、静的下限テストとauditを併用 | 親ツールの挙動変更を最小化し、auditの見逃しにも耐えられる |
| CR-P3 | registerのcatchで固定warnと元エラーを出し、そのまま完了 | PWAだけを安全に縮退させ、診断可能性とゲーム継続を両立できる |

### 4.2 不変条件

- 568×320で操作要素はviewportと右レールの内側に収まり、下端に2 CSS px以上の空きを持つ。
- すべての表示中サーブボタンと設定ボタンは幅・高さとも44 CSS px以上を維持する。
- `body[data-phase="serve"][data-server="P"]` 以外のラリー、AIサーブ、pause、titleの配置を変えない。
- `npm ci` がNode 24 / npm 11.11.0で再現でき、`npm run check` の全工程を維持する。
- Service Worker登録成功時は警告を出さず、既存PWA/offlineテストを維持する。
- Service Worker登録失敗時は未処理Promise rejectionを発生させず、タイトル表示と試合開始を利用可能に保つ。
- IndexedDB `table-tennis2` version 1、保存shape、PWAのname/id/start_url/scope、公開pathname `/sitar/table-tennis2/` を変更しない。

## 5. 詳細仕様

### 5.1 CR-P1：低高さcompactブレークポイント

`src/styles.css` の既存プレイヤーサーブ時ルールより後ろに、次の適用条件を持つmedia queryを追加する。

```css
@media (min-width: 568px) and (max-width: 759px) and (max-height: 360px) and (orientation: landscape) {
  /* 本節の右レール・サーブパネル調整 */
}
```

media query内では、全selectorを `body[data-phase="serve"][data-server="P"]` で状態限定し、既存ルールより後ろへ置く。後勝ち順序だけへ依存しない詳細度を確保し、次の値を初期正本とする。

| selector | property | v0.2.2値 | 契約 |
|---|---|---:|---|
| `body[data-phase="serve"][data-server="P"] .app-rail--right` | `gap` | `2px` | レール子要素間だけを圧縮する |
| 同上 | `padding-block` | `2px` | inline padding、border、safe-areaは変更しない |
| `body[data-phase="serve"][data-server="P"] .app-rail--right .serve-controls` | `padding-block` | `3px` | 左右paddingと枠線を維持する |
| `body[data-phase="serve"][data-server="P"] .app-rail--right .serve-controls__label` | `margin-bottom` | `2px` | ラベルを非表示にしない |
| `body[data-phase="serve"][data-server="P"] .app-rail--right .serve-controls__grid` | `gap` | `4px` | 3×3の球種ボタン間隔を維持する |
| `body[data-phase="serve"][data-server="P"] .app-rail--right .serve-controls__lengths` | `gap` | `4px` | 3個の長さボタン間隔を維持する |
| 同上 | `margin-top` | `4px` | 球種と長さの視覚グループを維持する |

- `.serve-choice` の `min-height: 44px`、font-size、文言、3列構成は変更しない。
- `.rail-action` の `min-height: 44px` は変更しない。
- `overflow: hidden` はゲーム画面全体の固定配置契約として維持し、欠陥をスクロールで隠さない。
- 2px以上の下端余白を満たせないブラウザがある場合は、上表のspacingを0未満にせず、ラベルfont-sizeを最小 `9px` まで縮小できる。ボタン高、文言非表示、要素削除は調整候補にしない。
- 760px以上、361px以上の高さ、portraitにはこのmedia queryを適用しない。

### 5.2 CR-P1：測定契約

E2Eの配置判定は固定値 `320` の直書きだけでなく、`window.innerHeight` と `#rightRail.getBoundingClientRect()` を基準にする。

```text
serveControls.top >= max(0, rightRail.top)
serveControls.bottom <= min(window.innerHeight, rightRail.bottom) - 2
各表示ボタン width >= 44 かつ height >= 44
```

- `568×320` の通常開始と `390×844 → 568×320` の回転復帰の両経路で測定する。
- `#leftRail` はhidden、stage上の両得点とmatch metaはvisible、サーブ種9個・長さ3個はすべてvisibleかつ操作可能であることを維持する。
- `759×360` でもcompact契約を満たすことを境界確認し、`760×360` ではleft railが表示される既存境界を維持する。

### 5.3 CR-P2：lockfile更新手順と許容範囲

1. Node 24 / npm 11.11.0で `npm audit fix --dry-run --json` または同等の読み取り確認を行い、提案される依存差分を保存せず確認する。
2. `brace-expansion` と `nanoid` だけを、親依存が許容する同一majorの修正版へlockfile上で更新する。
3. 解決結果は `brace-expansion >= 5.0.9` かつ5系、`nanoid >= 3.3.18` かつ3系とする。より新しい同一majorの修正版は許容する。
4. 第一選択は `package-lock.json` だけの間接依存更新である。npmの解決上それが不可能な場合だけ、`package.json` の `overrides` に対象2パッケージの修正版を追加する。
5. overridesでも解決できない場合は作業を止め、ESLint/Viteの直接更新が必要な理由、候補版、破壊的差分を設計追記してから進む。
6. `npm audit fix --force`、無関係パッケージの一括更新、Node/npm要件の変更は行わない。

`tests/app-contract.test.mjs` にlockfileを読み取る契約テストを追加し、対象ノードが存在すること、majorが想定どおりであること、修正版下限以上であることを検査する。比較は数値3要素の単純なsemver比較で足り、汎用semver依存は追加しない。

`npm audit --json` はhigh/critical 0件を受け入れ条件に含めるが、対象2パッケージの静的下限検査を代替しない。workflowへオンラインaudit stepは追加せず、PR/Pagesの `npm ci` と `npm run check` を再現性のある常設gateとする。

### 5.4 CR-P3：登録失敗の可観測化

`src/main.ts` の登録Promiseだけを次の契約へ変更する。

```ts
void navigator.serviceWorker.register(serviceWorkerPath).catch((error: unknown) => {
  console.warn("Service Worker の登録に失敗しました。", error);
});
```

- 警告は開発・本番を問わず出す。公開環境のscope、MIME、HTTPS、path不備を現地で診断できることを優先する。
- catch後にthrow/rejectせず、再試行、reload、cache削除、UI表示を行わない。
- Service Worker API非対応時は従来どおり何もしない。
- `serviceWorkerPath` 未定義時の構成エラーは従来どおりfail-fastする。
- 既存の登録成功、ready、controller、offline cache、世代分離テストは変更しない。

### 5.5 CR-P3：失敗系E2E

`tests/game-smoke.spec.js` に、アプリmodule実行前に `ServiceWorkerContainer.prototype.register` をrejectするテストダブルを設定する試験を追加する。

確認事項は次の4点とする。

1. consoleのwarningとして固定文言 `Service Worker の登録に失敗しました。` を1回観測する。
2. 元エラーを同じwarning引数から識別できる。
3. `pageerror` と未処理Promise rejectionを発生させない。
4. タイトル画面が表示され、開始ボタンを押してゲーム画面へ遷移できる。

成功系ではconsole warning/error 0件を維持する。失敗を注入した試験だけは上記1件のwarningを期待値とし、全体のconsole品質gateを緩和しない。

## 10. 代替案と不採用理由

| 代替案 | 不採用理由 |
|---|---|
| E2Eの `<=320` を `<=321` へ緩和する | 画面外クリップを許容し、製品要件をテスト側で弱めるため |
| ボタン高を43px以下へ縮める | 既存44pxタップ領域契約を壊すため |
| 右レールをスクロール可能にする | 最小画面の主要サーブ操作が見切れ、誤スクロールを招くため |
| サーブパネルをfixedへ戻す | stageやHUDとの重なり、right rail責務の崩壊を招くため |
| `npm audit` 0件だけでP2を完了する | 現時点で修正版未満のlockfileでも0件となり、対象指摘を検出できないため |
| `npm audit fix --force` を適用する | 親ツールの破壊的更新と広範なlockfile差分を招き得るため |
| ESLint/Viteを先にmajor更新する | 間接依存の同一major修正で解決できる可能性が高く、変更範囲が過大なため |
| Service Worker失敗をUIへ表示する | ゲーム本体は利用可能で、一般利用者へ不要なPWA内部エラーを露出するため |
| 登録失敗時に再試行・reloadする | 失敗loopや二重登録を増やし、今回の可観測化を超えるため |
| warningをdevelopment限定にする | 公開Pages固有のscope/path/MIME障害を現地診断できなくなるため |

## 11. リスク・ロールバック

| リスク | 予防 | 検出 | 回復 |
|---|---|---|---|
| spacing圧縮で可読性が落ちる | compact低高さ・player serveだけへ限定しfont最小値を定義 | 568×320 / 759×360 / 844×390のChrome・E2E | P1のmedia queryだけをrevertし、別値を本書へ追記して再調整 |
| 依存更新でlint/buildが変わる | 同一majorの間接依存だけを更新 | `npm ci`、全check、lockfile差分 | lockfile更新commitをrevertし、親依存更新案を別設計で検討 |
| auditデータが再変動する | 静的下限とauditを別gateにする | app contractとaudit出力 | 新advisoryの修正版下限を再調査し、本書へ追記 |
| warningが想定外に多発する | 登録reject時だけ1回出力し再試行しない | console E2E、公開Chrome | P3変更をrevertして黙殺へ戻すのではなく、原因修正後に警告頻度を再評価 |
| v0.2.2 cache名不整合 | package versionとcache名を同時同期 | `check:app` / `check:dist` / PWA E2E | package/lock/cacheを同じ版へ戻す |

ロールバックは対象commitの `git revert` を使用し、reset、force push、保存データ削除を行わない。schema変更がないためmigration/backfill/DB rollbackは不要である。公開rollback時はroot+child合成artifactと最終deployment SHAを再確認する。
