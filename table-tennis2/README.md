# 卓球 横画面（table-tennis2）

既存 `table-tennis` v0.6.2 のゲーム仕様を独立継承し、スマートフォン横画面を主対象にする1人用3D卓球ゲームです。PWAに対応しており、ホーム画面へ追加すると既存版とは別アプリとして起動できます。v0.2.4では、返球が相手コートへ届かない構造的欠陥を必要速度フロアで解消し、初級・中級・上級をAI球速・AI精度・接触補助・品質下限・返球誤差の5軸で分離しました。難易度選択には、何が変わるかの説明文を添えています。

v0.3.0では、ゲームシステム（物理・AI・接触判定・乱数・ルール・保存・PWA）を変えずに描画とHUDだけを刷新しました。会場を観客席のある暗めの試合会場にし、背景と台をオフスクリーンキャッシュへ移して、接触スパーク・バウンドリング・ネット揺れ・スマッシュ集中線・死球の残留といったイベント駆動の演出を追加しています。得点者と理由は新しい得点バナーが文字で示し、デュース／マッチポイントの状況チップ、接触品質ラベル、サーブ着地帯の目安、回転の色分けも加えました。

## 横画面HUD

- 得点は相手をstage左上、プレイヤーをstage右上に表示します。
- 難易度とラリー数は上部中央の小型表示にまとめます。
- 幅760px以上ではleft railに現在のサーバーを表示します。
- right railから設定を開け、ラリー中は音と振動も直接切り替えられます。
- 568〜759pxではleft railを隠しても、両得点とサーバー点はstage内に残ります。
- 568×320〜759×360の低高さ横画面では、プレイヤーサーブ時だけright railの余白を圧縮し、44px以上の操作領域と下端2px以上の余白を維持します。

## 遊び方

### サーブ

プレイヤーのサーブ時は、画面下部から種類と長さ（短い／中／長い）を選び、台上をタップまたは左右にフリックしてサーブします。

- 横上左
- 上回転
- 横上右
- 横左
- ナックル
- 横右
- 横下左
- 下回転
- 横下右

選択した種類と長さは同じページを開いている間、ポイントや再試合をまたいで保持されます。

サーブを選んでいる間は、選んだ長さがどのあたりへ落ちるかの帯を相手コートへ表示します。**この帯は目安です。** 狙いが台から大きく外れる入力では内部の解探索が狙いや長さを切り替える（中サーブへ寄せる）ことがあるため、実際に打たれた長さは打球直後のトースト（例: `ナックルサーブ（中）`）が示します。

### ラリー

- スマートフォン: 画面をドラッグすると、ラケット中心が指より画面高の6%上をX/Y両方向へ追従します。
- PC: マウスをドラッグすると、ラケット中心がポインターより画面高の1%上をX/Y両方向へ追従します。
- ポインターイベントの間は最大16msだけ移動方向を予測し、描画と衝突は同じラケット中心を使います。
- 相手の返球が自陣でバウンドすると、現在軌道から予測した迎球位置を緑色のリングで短く表示します。リングへ自動吸着はせず、実際のラケット位置と奥行きが合ったときだけ返球します。
- ラリー中は接触可能範囲を白い補助輪郭で表示します。touchはbladeの1.40倍、mouse / penは1.20倍を目安とし、ボール外周が輪郭内へ入り、奥行きも合ったときだけ返球します。成立した接触は最低0.40の品質を持ち、明確に外すと従来どおり空振りになります。
- 指を離した後もtouchは350ms、mouse / penは220msまで最後の位置で接触できます。ただし技判定の鮮度は160msのままで、161ms以後の接触は弱い「押し出し」になります。離した後の猶予は最初の接触で消費します。
- ボールへ位置を合わせるだけの左右移動や遅い上下移動は、弱い「押し出し」として返球します。返球コースは補助輪郭内の接触位置で決まります。
- 上フリック: ドライブ。高い球を強く振るとスマッシュ。
- 下フリック: ツッツキ。
- 短い球: 下フリックでストップ、上フリックでフリック。
- 指やマウスを置くだけ: 押し出し。
- 直前80msに十分な速さ・変位を持つ明示的な上下ストロークだけが、ドライブ、スマッシュ、ツッツキなどの技になります。
- 明示的な上下ストローク中に曲線を描いた場合だけ、曲がる向きに応じて横回転が加わります。
- right railの設定ボタン: 一時停止画面を開く。
- ラリー中の音・振動ボタン: 効果音と振動を直接切り替える。

### 画面から読み取れること（v0.3.0）

- **得点バナー**: 得点が決まると、誰の得点か（`あなたの得点` / `あいての得点`）と理由（ネット／アウト／返せず／サーブフォルト／自陣に落下）を画面中央上寄りに文字で表示します。色は補助で、色だけに依存しません。通常1.1秒、試合を決める得点は0.95秒でリザルト画面へ引き継ぎます。
- **死球の残留**: 得点が決まった球は即座に消えず、落ちた場所に0.5秒静止してから0.75秒かけて消えます。試合を決める最後の1点でも同じように表示します。
- **状況チップ**: 10-10以降は「デュース」、次の1点で決まる局面では「マッチポイント」「相手マッチポイント」を上部中央に表示します。
- **接触品質ラベル**: 自分の返球では、打球名の後ろに `ジャスト` / `ナイス` / `OK` / `ギリギリ` が付きます。全難易度で常に表示します。
- **回転の色分け**: 入射球の軌跡と回転線が、上回転で暖色、下回転で寒色になります。
- **最長ラリー**: リザルト画面にその試合の最長ラリー数を表示します。

### モーション軽減と一時停止

- OSの「視差効果を減らす」（`prefers-reduced-motion: reduce`）を有効にすると、粒子・集中線・ネット揺れ・得点パルス・相手の待機の揺らぎが止まります。得点バナー・状況チップ・死球・着地帯・バウンドリング・回転色などの情報表示は残ります。
- 一時停止・タブ非表示・縦画面ガード中は、エフェクトと相手の揺らぎが静止し、トーストと得点バナーの残り時間はそのまま保持されます。復帰時に演出が飛ぶことはありません。

### ラケットの見え方

ラケットにはブレードと持ち手が描かれます。プレイヤー側は通常の位置合わせ中はニュートラル姿勢を保ち、明示的なactive strikeの間だけ入力方向へ傾きます。接触時に短く光った後、待機位置へ戻ります。相手のラケットは従来どおり、持ち手が腕の向きに合わせて描かれます。

打つ位置が台に近い（奥の）ときはラケットが小さく、手前のときは大きく描かれます。描画と衝突判定は同じ投影式とラケット姿勢を使うため、見た目と当たり判定のずれを抑えています。

比較や緊急回避が必要な場合だけ、URLへ `?controlModel=legacy` を付けるとv0.1.1までの左右位置指定・接触面返球へ一時的に戻せます。この指定は保存されません。入力軌跡と接触観測値は `?debugInput=1` で開いた開発確認時だけ表示します。

## プレイヤーと戦績

タイトル画面の「プレイヤー」から、この端末で遊ぶ人を追加・選択・改名・削除できます。初回は `ゲスト` が自動作成されます。選択した名前はスコアボードへ反映され、決着した試合だけがそのプレイヤーの戦績として保存されます。

「戦績」では、次の内容を確認できます。

- 通算の試合数、勝敗、勝率、最高ラリー
- 初級・中級・上級ごとの試合数と勝数
- 直近10試合の日時、難易度、スコア、最大ラリー、試合時間

記録はブラウザの IndexedDB に保存され、外部へ送信されません。保存先は現在使っているブラウザ・端末内だけです。別の端末やブラウザとは同期されず、ブラウザのサイトデータを削除すると記録も消えます。プレイヤーを削除した場合は、そのプレイヤーの戦績も一緒に削除され、元に戻せません。

## 開発環境

Node.js 24とnpmを使用します。初回のみ依存関係とテスト用ブラウザを導入してください。

```powershell
npm ci
npx playwright install chromium webkit
```

開発サーバーを起動します。

```powershell
npm run dev
```

その後、`http://localhost:3039/` を開きます。同一ネットワーク内のスマートフォンからは、PCのIPアドレスを使って確認できます。

横向き568×320以上が必要です。568〜759px幅ではstageとright rail、760px以上ではleft rail・stage・right railを表示します。両得点はどちらの幅でもstage上隅に表示されます。568×320〜759×360のプレイヤーサーブ時は、44px以上の操作領域を保ったまま、サーブ操作パネルとright rail下端の間に2px以上の余白を確保します。縦画面または最小未満ではゲームを停止し、回転案内を表示します。

## 検証

```powershell
# ESLint、TypeScript、PWA構成、build、dist、単体、ブラウザテスト
npm run check

# 個別実行
npm run lint
npm run typecheck
npm run check:app
npm run build
npm run check:dist
npm run test:unit
npm run test:e2e
npm run test:e2e:stability
```

lockfileは `brace-expansion` 5系 `>=5.0.9` と `nanoid` 3系 `>=3.3.18` を静的に検査します。Service Workerの登録に失敗してもゲームは継続し、ブラウザコンソールへ固定警告と元エラーを出力します。

ブラウザテストは次の3環境で実行します。

- デスクトップ版Chromium
- Android相当Chromium
- iPhone相当WebKit

## ビルドとプレビュー

```powershell
npm run build
npm run preview
```

ビルド出力は `dist/` です。アプリ本体はService Workerの事前キャッシュ対象となる固定名で出力します。

- `dist/assets/app.js`
- `dist/assets/app.css`

manifest、Service Worker、`.nojekyll`、iconsも `dist/` へコピーされます。

## GitHub Pages

`master`へのtable-tennis関連push時に、`.github/workflows/deploy-table-tennis-pages.yml` が次を行います。

1. Node.js 24と依存関係を準備。
2. PlaywrightのChromiumとWebKitを準備。
3. `table-tennis` と `table-tennis2` の両方で `npm run check` を実行。
4. 既存版をroot、新規版を `/table-tennis2/` に配置した `_site/` を検査。
5. 合成した `_site/` をPages artifactとしてデプロイ。
